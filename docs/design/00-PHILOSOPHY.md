# 00 · Philosophy

**Vesper is a precision instrument for shaping sound.**

Engineered, not decorated — the register of a Leica body, a Braun face,
laboratory equipment: calm, exact, permanent. The interface must feel
machined from one block, and it must disappear while the music remains.

This document governs a **product family**, not a screen. Plugins,
standalone apps, hardware, mobile companions and the website all derive
from the same language. Layouts are implementations (see 08); the language
must survive their complete replacement.

## The identity thesis

Vesper is recognized by **proportion, typography, spacing, geometry,
motion and restraint — never by color, and never by any single layout
element.** The language is five primitives (01) composed with a fixed
proportion system. A future Vesper product designed by someone who has
never seen today's screens, using only these documents, must be
recognizably Vesper.

## Emotional contract

The user should become *calmer* after opening Vesper. The emotional goal
is **trust**; the visual goal is **clarity**; the interaction goal is
**flow**. Confidence compounds: every interaction must leave the user more
certain of what just happened, never less.

## Laws

1. **Nothing decorative.** Every visible element encodes a value, a state,
   or a boundary. If deleting it loses no information, delete it.
2. **The language outranks any component.** A component that doesn't fit is
   redesigned; the language is never weakened to admit it.
3. **Light is meaning.** Accent marks live values and active states only.
   Rest is quiet ink. When something glows, it matters.
4. **Typography carries hierarchy.** Size, weight and emphasis rank
   information. Color never does.
5. **Space is composed** (01, Space primitive). Dead space is a defect;
   composed silence is structure.
6. **Motion explains** — what changed, where it went, why (04). An
   animation answering none of these is deleted.
7. **Stability builds memory.** Controls do not move between versions
   without a usability reason. Muscle memory is a feature we ship.

## Gates (every release, every major design)

- **Ten-year test** — would this decision still make sense in 2036?
- **8-hour test** — still beautiful, untiring, undistracting after a full
  studio day? Optimize for the thousandth hour, never for screenshots.
- **Recognition test** — remove logo, color, and text: do proportions,
  spacing, geometry and motion still identify Vesper? If not, the language
  (not the logo) is what's broken.
- **Simplicity interrogation** — for every addition: can it be removed?
  Can two controls become one? Can typography replace an icon, spacing
  replace a divider, hierarchy replace color, motion replace a label?
  Complexity is admitted only when it reduces the user's effort.

## Authority

Every UI decision cites these documents. Ad-hoc visual decisions are
defects. The language changes here first, then in code (07 mirror
contract). This system is versioned: **v1.0** (ratified after the v0.9
review — D-016/D-017).
